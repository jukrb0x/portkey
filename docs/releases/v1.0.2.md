# PortKey v1.0.2

Fixes editing and enabling an existing macOS profile without recreating its display and USB setup.

- Adds **Edit setup** for saved profiles, preserving the exact display, USB topology and input mapping. Saves update the original profile.
- Replaces the repeated setup wizard for existing profiles with a focused check-and-enable page. Missing requirements are explained inline; enabling saves observations and the profile together.
- Provides explicit switch tests, including a cancellable ten-second delay for testing return from the other computer’s picture. Input readings and successful commands never automatically count as visual confirmation.
- Keeps saved connection mappings across sleep and temporary display loss while cancelling pending commands and ownership. Recovers interrupted existing-profile drafts without restoring stale qualification.
- Fixes tests stuck in a pending state after display loss and validates explicitly selected displays before a new profile has been saved.

The user reported the updated work-profile flow working on the enrolled setup. Automated validation covers the shared Rust core and native builds; this does not establish universal hardware compatibility or new sleep/wake qualification. The Windows package includes the shared controller fixes and matching release version; the new editing interface is macOS-specific.

Packages: macOS arm64 and Windows x64, with SHA-256 checksums. macOS is ad-hoc signed, without Developer ID notarization; Windows is unsigned and requires the Microsoft Windows App SDK runtime. Existing profiles are preserved.
